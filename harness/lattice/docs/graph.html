Lattice — Harness 0.1 · Graph d'exécution par agent

Qui exécute quoi, dans quel ordre, avec quelles garde-fous — la suite Lattice (23 cartes, 4 vagues), construite par agents et validée par un humain.

① La boucle d'agents — un cycle de carte
② Les 22 cartes — par vague et par agent (chemin critique en jaune)

Qui fait quoi

  • • Orchestrateur · Hermes — planifie, génère les prompts, court les gates, tient STATE.md. Ne code jamais.
  • • Codeur · sous-agents via la chaîne OMH — une carte à la fois, fichiers owns seulement, sort ses fichiers + NOTES + DEVIATIONS.
  • • Relecteur · catégorie OMH review — verdict PASS / FIX / ESCALATE, contrats avant tests.
  • • Humain (toi) — checkpoints H10-H14, décide les déviations, gèle le contrat après H11.

Ordre d'exécution

  • • L1 d'abord, seul (tout le projet bouge) → gates → revue → H10.
  • • Vague 0 en parallèle (L2-L5), ≤4 cartes, owns disjoints → H11 (gel du contrat).
  • • Vagues 1 et 2 indépendantes (glyphes / glitch) → H12 puis H13.
  • • Vague 3 séquentielle : L21 → L22 (recette PhotoCraft + DesignCraft) → H14.
  • • Chemin critique : L1 → L2 → L12/L20 → L21 → L22. Toujours prioriser L1 puis L2.

Garde-fous

  • • Gates G1-G4 (ruff, pytest, check_contract, owns) + G7 régression du core (bit à bit) + G8 renderers + G9 parité CLI/GUI.
  • • 3 retries de gates, 2 cycles de revue, puis déviation E1-E9 → décision humaine.
  • • E8 : aucune fuite core→app · E9 : chaque app marche sans hôte.
  • • L1 impose les baselines PNG avant de toucher au code — G7 compare au bit près.
